# D1-024 — Non-régression et rollback

Date : 7 novembre 2026  
Périmètre : **site de démonstration WOOD uniquement**. Aucun paiement, e-mail
commercial, commande réelle, appel d'écriture Supabase ou opération distante
Cloudflare n'est activé.

## État validé

- La bascule D1 reste désactivée par défaut : `WOOD_D1_DEMO_ENABLED` doit être
  exactement `true` pour qu'une lecture réseau soit tentée.
- En cas d'absence, d'erreur ou de quota du Worker, le catalogue local reprend
  la main : c'est le **fallback local** ; le parcours démo ne reste pas vide.
- La version de base et la version démo restent séparées sur GitHub Pages.
- Le point de retour applicatif est le commit `dd8de27` ; les lots précédents
  restent réversibles individuellement par `git revert`.

## Scénario de retour arrière immédiat

1. Remettre `WOOD_D1_DEMO_ENABLED` à sa valeur par défaut désactivée, ou
   supprimer l'opt-in de la configuration démo.
2. Retirer l'URL Worker de la configuration publique et republier le paquet
   statique ; le catalogue local reste la source de secours.
3. Arrêter le Worker ou son déclenchement, sans supprimer D1 et sans supprimer
   Supabase. **Ne pas supprimer D1, ne pas supprimer Supabase.**
4. Vérifier la racine de sauvegarde et `/demo/` avec
   `npm run verify:pages-package`, puis relancer `npm run check`.
5. Si le lot visuel doit être annulé, revenir au commit de retour validé par
   `git revert dd8de27` (ou au point de retour retenu par l'équipe), sans
   toucher aux données externes.

## Limites honnêtes

La recette sur appareil Safari iOS, Android réel, Firefox réel et les décisions
Cloudflare nécessitant un compte restent ouvertes dans leurs tâches dédiées.
Ce ticket prouve le garde-fou local et le retour arrière non destructif ; il ne
prétend pas valider une offre Cloudflare distante ni une publication
commerciale.
